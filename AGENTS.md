# Code documentation

- Comment code you add or modify. Use docstrings to explain module, class, and
  function responsibilities, and inline comments to explain important choices,
  lifecycle behavior, assumptions, and non-obvious logic.
- Apply this preference to tests and hand-maintained configuration as well.
  Keep comments useful and accurate rather than restating every line.
- Do not hand-edit generated files such as `uv.lock` to add comments.
